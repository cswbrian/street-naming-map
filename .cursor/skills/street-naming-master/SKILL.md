# Street naming master file

**Contributor docs:** [README — Data model](../../README.md#data-model-read-this-first)

## Source of truth

**One file:** `data/master/street-events.json`

```json
{
  "schema_version": 1,
  "updated_at": "2026-06-07T…",
  "events": [ /* flat array, sorted by publication_date */ ]
}
```

All sources live here: `crowdsubmitted`, `hkgro`, `landsd`, `egazette_pdf`.

Event field reference: `docs/street-name-history-schema.md`

**Event types and `history[]` patterns:** [event-model.md](../event-model.md) — same classification used by parse-hkgro-gazettes and apply-egazette-naming.

**Gazette PDFs:** [.cursor/skills/gazette-files/SKILL.md](../gazette-files/SKILL.md) — `notice_stem`, paths, publish, lint.

## After any edit

```bash
npm run backfill:notice-stems   # if gazette URLs/stems changed
npm run lint:gazettes
npm run rebuild:naming && npm run report:pending-years
```

Optional: `npm run build` before deploy.

## Insert a new event

1. Resolve `street_code` from `public/data/hk-streets.geojson` or `public/data/master/pending-roads.json` (prefer code + Chinese name — never English alone when homonyms exist).
2. Add an object to `events[]` with a **unique** `event_id`.

**`event_id` pattern:** `{source}|{batch-or-notice-slug}-{street_code}-{publication_date}`

Example: `crowd|1909-gn184-taku-12326-1909-03-19`

**Minimum fields for a gazette-backed declaration:**

```json
{
  "event_id": "crowd|1909-gn184-taku-12326-1909-03-19",
  "source": "hkgro",
  "street_code": "12326",
  "publication_date": "1909-03-19",
  "change_kind": "declare",
  "street_name_en": "Taku Street",
  "street_name_zh": "大沽街",
  "previous_street_name_en": null,
  "previous_street_name_zh": null,
  "event_role": "current_name",
  "evidence_kind": "gazette_primary",
  "is_declaration_event": true,
  "notice_no": "GN184",
  "government_notice_label_en": "G.N.184",
  "government_notice_label_zh": "第184號",
  "government_notice_url_en": "/egazette/en/1909-gn184.pdf",
  "government_notice_url_zh": "/egazette/zh/1909-gn184.pdf",
  "notice_type_normalized": "declare",
  "year_bucket": 1909,
  "evidence_level": "gazette"
}
```

For renames, set `change_kind: "rename"`, fill `previous_street_name_*`, and set `event_role` (`current_name` vs `former_name`).

For **Previous G.N.** citations: `evidence_kind: "gazette_inferred"` + `derived_from[]` (see schema doc).

3. Keep `events` sorted by `publication_date` (script re-sorts on save if using helpers below).

## Amend an existing event

Find by `event_id` (grep the file). Patch fields in place — do **not** change `event_id` unless intentionally replacing a row.

Common patches:
- Add/fix `government_notice_url_en` when a PDF is published under `public/egazette/`
- Upgrade `evidence_kind` from `unknown` → `gazette_primary`
- Fix `publication_date`, `street_code`, or name fields after gazette review

## Remove an event

Delete the object from `events[]` by `event_id`. Then rebuild.

## Optional: use library helpers (scripts)

From `scripts/lib/master-street-events.mjs`:

| Function | Use |
|----------|-----|
| `loadMasterEvents()` | Read current events |
| `saveMasterEvents(events)` | Write file with sort + `updated_at` |
| `upsertMasterEvents(master, incoming)` | Insert or replace by `event_id` |
| `patchMasterEventById(events, id, patch)` | Amend one row |
| `removeMasterEventById(events, id)` | Delete one row |
| `findMasterEventsByStreetCode(events, code)` | Timeline for a street |

## Gazette batch workflow (optional)

If a PDF notice covers many streets, you may still use:

```bash
node scripts/parse-crowd-gazette-pdf.mjs "/path/to/notice.pdf" --match
node scripts/apply-crowd-batch.mjs data/crowdsubmissions/batches/{batch}.json
```

`apply-crowd-batch` upserts into `data/master/street-events.json` and runs rebuild. You can skip this and paste events into the master file directly.

## Import paths (rare)

| Script | When |
|--------|------|
| `npm run merge:egazette` | Bulk-import parsed eGazette events (adds new rows; master wins on conflicts) |
| `npm run import:crowdsubmissions` | Legacy Google Form CSV → master |

## Do not edit

- `public/data/hk-streets.geojson` naming fields — generated by `rebuild:naming`
- `public/data/master/verified-roads.json` / `pending-roads.json` — generated by `report:pending-years`
- Deleted legacy files: `street-events-combined.json`, `street-aggregates-combined.json`, `data/crowdsubmissions/street-events.json`

## QA checks

```bash
# Event count by source
node -e "const s=require('./data/master/street-events.json'); const c={}; s.events.forEach(e=>c[e.source]=(c[e.source]||0)+1); console.log(c, 'total', s.events.length)"

npm run rebuild:naming
npm run report:pending-years
npm run build
```

Spot-check a street on the map: centerline year should match `map_year` (built-first, else naming); chip 來源 link should match the `current_name` event with strongest `evidence_kind`.
